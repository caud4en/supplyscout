You are an expert in TinyFish API systems, data engineering, and production-grade data validation pipelines.

The current implementation is functional, but a critical issue exists: many of the stored company/industry website links are invalid or not real. This compromises the integrity and reliability of the system.

Your task is to rebuild the dataset and databases (both development and production) to ensure that only verified, legitimate company websites are included, while preserving all previously defined system requirements.

Objectives
Data Quality Audit
Analyze the existing database and identify all entries with invalid, broken, or non-existent company/industry website links.
Define clear validation criteria for what constitutes a “real and proper” website (e.g., reachable domain, valid DNS, meaningful content, no placeholders).
Database Reset & Reconstruction
Safely remove all existing entries from both development and production databases.
Recreate the dataset from scratch while:
Maintaining the same total number of entries as previously required (≥10,000 rows)
Preserving schema structure and compatibility with the TinyFish pipeline
Verified Data Ingestion Pipeline
Design and implement a robust ingestion pipeline that:
Sources company/industry data from reliable online sources (APIs, directories, datasets)
Verifies each website before insertion using:
DNS resolution checks
HTTP(S) response validation (status 200, valid SSL, etc.)
Basic content verification (non-empty, relevant page content)
Filters out invalid or suspicious entries
RAG Compatibility
Ensure the cleaned and verified dataset integrates seamlessly with the existing retrieval-augmented generation (RAG) pipeline
Maintain proper structuring for embeddings, indexing, and retrieval
Consistency Across Environments
Ensure both development and production databases:
Contain identical, verified datasets after reconstruction
Follow the same persistence and append-only principles going forward
Data Integrity & Validation
Implement validation checks such as:
Row count verification (ensuring required dataset size is met)
Duplicate detection and prevention
Periodic re-validation of stored links
Scalability & Reliability
Ensure the pipeline can continuously add new verified entries without degrading data quality
Handle failures (e.g., unreachable sites, API issues) with retries and fallback logic
Constraints
All previous requirements remain unchanged, including:
Minimum dataset size (≥10,000 rows)
Persistent, append-only database behavior after reconstruction
Compatibility with the TinyFish pipeline and RAG system
Only fully verified, legitimate websites may be stored
The system must avoid introducing invalid data in future updates
Output Requirements
Provide:
A high-level system architecture for data validation and ingestion
A step-by-step reconstruction plan for both development and production databases
Suggested validation techniques and tools (e.g., HTTP checks, domain validation libraries)
Key code snippets or modules for verification and ingestion
A data quality assurance and monitoring strategy
