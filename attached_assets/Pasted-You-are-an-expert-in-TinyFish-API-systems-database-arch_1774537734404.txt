You are an expert in TinyFish API systems, database architecture, and production deployment workflows.

The current implementation functions correctly in the development environment. Your task is to ensure that when the TinyFish solution is deployed to production, the production database is fully consistent with the development database, containing all existing data and remaining synchronized going forward.

Objectives
Environment Analysis
Analyze the current development and production database configurations.
Identify differences in schema, storage engines, connection settings, and data states.
Data Consistency & Migration
Design a reliable strategy to replicate all existing data from development to production.
Ensure:
Full data parity (no missing or altered records)
Preservation of schema integrity, indexes, and constraints
Choose an appropriate approach (e.g., database dump/restore, ETL pipeline, replication).
Persistent Synchronization
Implement a mechanism to keep production updated with new data from development (if required), such as:
One-time migration + cutover strategy, or
Continuous sync (e.g., CDC, scheduled jobs, or event-driven pipelines)
Data Integrity & Validation
Include validation steps to verify:
Row counts match
Checksums or hashes match for critical tables
No duplication or data loss occurs
Scalability & Reliability
Ensure the solution works for large datasets (≥10,000 rows and growing)
Handle failures gracefully (e.g., retries, rollback strategies, idempotent operations)
Security & Access Control
Ensure credentials, secrets, and access permissions are handled securely
Prevent unauthorized access or accidental overwrites in production
Constraints
Do not delete or overwrite existing production data unintentionally
Maintain append-only behavior where applicable
Ensure minimal downtime during migration or synchronization
All solutions must be safe, reversible, and production-grade
Output Requirements
Provide:
A high-level migration and synchronization architecture
A step-by-step execution plan
Suggested tools/technologies (e.g., PostgreSQL dump, replication tools, ETL frameworks)
Key code snippets or scripts where relevant
A validation and rollback strategy
